## P0 近期优先

### 1. 工作区外 assets 依赖

不应监听工作区外依赖，因为外部依赖一般不会改动，但可以提供一个手动刷新的按钮以防万一

实施清单：

- [x] 新增手动刷新按钮

### 2. Issues 和 Dependencies 点击跳转

价值：

- 当前 issue 已携带 `resourceUri`，但 UI 只能看文本，调试缺失父模型、缺失纹理、非法字段时仍要手动定位。
- 这是低成本、高频使用的调试效率提升，也能复用项目已有资源跳转能力。

实施清单：

- [x] issue 项支持点击打开对应资源文件。
- [x] 能定位 JSON range 时跳转到具体位置。
- [x] dependency 项支持点击打开模型、纹理或 metadata 文件。
- [x] 缺失文件点击时给出明确提示，不静默失败。
- [x] 为 webview 到 extension host 的 `openResource` 消息补单测或至少消息协议静态测试。

验收标准：

- 缺失纹理、缺失父模型、非法 JSON 或字段越界等 issue 可以直接打开相关文件。
- 不可定位的问题仍能展示资源路径和清晰说明。

### 3. Webview 显式 dispose 和泄漏验证

价值：

- 预览器会创建 renderer、controls、texture、geometry、material，长时间使用 VS Code 时泄漏会逐步拖慢体验。
- 当前刷新时已有资源释放，但页面 unload 和 panel dispose 的 webview 端释放不完整。

实施清单：

- [x] 在 webview unload、面板 dispose 或 host 下发 dispose 消息时显式释放 renderer、controls、texture、geometry、material。
- [x] 清理事件监听、resize observer、requestAnimationFrame 状态和截图等待状态。
- [x] 给重复打开/关闭预览增加手动验证记录，至少确认控制台无 WebGL/context 相关错误。
- [x] 若成本可控，加入 headless webview 级别的基本资源释放自查。

验收标准：

- 连续打开、刷新、关闭多个模型预览后无明显内存增长、控制台错误或失效的截图 promise。
- 面板关闭后不会继续触发 render 或文件刷新消息。

### 4. 性能基准和过期任务取消

价值：

- “高性能、低阻塞”目前主要靠设计和经验保证，缺少大模型基准。
- 用户快速切换模型、保存风暴或大模型烘焙时，取消过期任务比继续完成旧任务更有价值。

实施清单：

- [x] 建立普通模型、复杂父链模型、500 elements 模型的基准 fixture。
- [x] 记录首次生成 IR、热刷新、纹理加载等待、截图等待的耗时。
- [x] 将 cancellation token 或等价版本号机制下沉到解析、resolve、bake 阶段，丢弃过期结果。
- [x] 若 500 elements 烘焙阻塞明显，再考虑分片或 yield。
- [x] 将性能基准结果写入测试说明或 docs/review 记录，避免后续退化无感知。

验收标准：

- 普通模型 IR 生成和热刷新有可重复测量数据。
- 快速切换文件时，旧预览结果不会覆盖新预览，也不会继续占用不必要的计算。

## P1 下一轮产品能力

### 5. 导出图片 UI 选项

价值：

- 内部截图命令已有选项基础，但 UI 导出按钮没有暴露宽高、透明背景等常用设置。
- 资源包作者常需要把预览图用于对比、反馈或文档，导出可配置能扩大功能使用面。

实施清单：

- [x] 导出入口支持宽度、高度、透明背景和背景色。
- [x] 导出结果反映当前视角、显示模式、网格和坐标轴状态。
- [x] 失败时返回结构化错误，并在 UI 中给出可理解提示。
- [x] 截图命名模板暂不优先做，除非后续出现批量导出需求。

验收标准：

- 用户可从 UI 导出指定尺寸 PNG。
- 透明背景和自定义背景色在导出文件中可见且稳定。

### 6. 资源图节点打开预览

价值：

- 项目已有资源图侧边栏，预览器若能从模型节点直接打开，会形成完整的“发现资源到检查模型”工作流。
- 这项比新增孤立功能更能提升扩展整体连贯性。

实施清单：

- [x] 在资源图模型节点增加打开模型预览命令。
- [x] 对 blockstate、item definition 等暂不支持节点，先禁用或提示后续能力。
- [x] 保持资源图扫描策略不因预览功能增加额外全量负担。
- [x] 补充命令注册和菜单贡献测试。

验收标准：

- 从资源图中的模型资源可直接打开对应预览。
- 不增加资源图刷新卡顿或额外大范围扫描。

### 7. 缓存分层与纹理尺寸缓存

价值：

- 当前 preview cache 粒度偏粗，随着 blockstate、item definition、动画纹理扩展，重复解析和重复读取纹理尺寸会变成明显成本。
- 这项应以性能基准为依据推进，避免为抽象而抽象。

实施清单：

- [x] 将 raw model document、resolved model、preview IR 的缓存边界定义清楚。
- [x] 纹理尺寸读取单独缓存，按 URI 和 mtime/version 失效。
- [x] 配置变更、父模型变更、纹理变更时只失效必要层级。
- [x] 跨刷新 texture/material registry 复用作为后续优化，不作为第一步强制目标。

验收标准：

- 重复打开同一依赖链模型时解析和纹理尺寸读取次数明显下降。
- 缓存失效后不会展示旧父模型、旧纹理或旧 UV 结果。

## P2 有价值但应后置

### 8. Blockstate 预览 adapter

价值：

- 方块资源包制作中，用户经常从 blockstate 而不是单个 model 入口理解最终效果。
- 这项能显著扩大预览器覆盖面，但复杂度高于模型 JSON 预览，应作为独立 adapter 接入。

实施清单：

- [ ] 只做 blockstate 到 `PreviewDocument` 的 adapter，不让 webview 直接理解 blockstate JSON。
- [ ] 先支持 variants 和 multipart 的常见静态组合。
- [ ] UI 支持选择 variant 或展示可用变体列表。
- [ ] 对随机权重、状态条件和复杂组合保持近似说明。

验收标准：

- 常见 blockstate 可以选择状态并预览最终模型组合。
- 不支持的复杂行为进入 issue，而不是失败或静默忽略。

### 9. Item definition 预览 adapter

价值：

- 新版资源包中 item definition 重要性提高，但完整 item stack component 模拟不应进入简单渲染器范围。
- 适合做“解析入口和常见模型分支预览”，而不是游戏级物品渲染。

实施清单：

- [ ] 将 item definition 解析为一个或多个候选 `PreviewDocument`。
- [ ] UI 提供候选分支选择。
- [ ] 明确不模拟完整 item stack component，只展示能静态解析的模型路径。
- [ ] 对条件、特殊 renderer 或动态组件输出 issue。

验收标准：

- 常见 item definition 可以打开并预览关联模型。
- 动态或无法静态确定的分支有清晰提示。

### 10. `.png.mcmeta` 动画纹理播放

价值：

- 当前只预览动画纹理首帧，作者无法快速检查帧序、帧时长和插值配置。
- 这项用户价值明确，但会引入连续 render loop，需要谨慎控制性能。

实施清单：

- [ ] 解析 `.png.mcmeta` 的 animation 基础字段。
- [ ] 仅在用户启用播放时开启连续 render loop。
- [ ] 提供播放、暂停、帧步进和速度控制。
- [ ] 截图默认使用当前帧。

验收标准：

- 动画纹理可以在模型预览中播放和暂停。
- 关闭播放后恢复按需渲染，不持续占用 requestAnimationFrame。

### 11. Atlas `single` / `directory` 简化解析

价值：

- atlas 会影响纹理定位，简化支持可减少“文件实际存在但预览找不到纹理”的误判。
- 适合作为资源路径解析能力的补充，不应扩展到完整游戏 atlas 管线。

实施清单：

- [ ] 先支持 `single` 和 `directory` 两类高频 atlas source。
- [ ] 将 atlas 结果纳入纹理解析和依赖列表。
- [ ] 对复杂 source 记录 issue，保持预览不中断。

验收标准：

- 使用常见 atlas source 的资源包可以正确定位纹理。
- atlas 配置变化能触发相关预览刷新。

## P3 仅在明确需求后投入

### 12. Tint 颜色模拟

价值：

- tint 能改善草、树叶、水或部分物品的视觉接近度。
- 但它容易滑向“游戏级渲染一致性”，需要严格限定为可关闭的近似预览。

实施清单：

- [ ] 仅做常见 tintindex 的近似颜色映射。
- [ ] UI 提供开关，默认不影响基础 textured 预览。
- [ ] issue 中继续说明 tint 是近似行为。

验收标准：

- 开启后常见 tint 模型有可辨认颜色变化。
- 关闭后回到当前基础纹理预览。

### 13. Hover 显示 face、纹理 slot、UV 信息

价值：

- 对调试 UV、纹理变量和面朝向有帮助。
- 需要稳定 picking 和 UI 展示，收益低于点击跳转和 blockstate。

实施清单：

- [ ] 鼠标 hover 面时显示 face、texture slot、resolved texture、UV 和 rotation。
- [ ] 保证 hover 不触发持续高成本计算。
- [ ] 与 OrbitControls 拖动状态互不干扰。

验收标准：

- 用户可以在模型上定位某个面对应的纹理和 UV。
- 快速移动鼠标不造成明显卡顿。

### 14. Item display transform 调试

价值：

- 这项本质上只是把 item model `display` 里的旋转、平移和缩放应用到预览姿态，不能提升模型解析、贴图定位或资源依赖可靠性。
- 只有当用户明确在调物品手持、GUI、展示框等显示姿态时才有价值，不应作为简单模型渲染器的主要迭代。

实施清单：

- [ ] 仅在有明确需求时增加 `gui`、`ground`、`fixed`、`thirdperson` 等姿态切换。
- [ ] 将能力限定为 item display transform 调试，不扩展成游戏级物品渲染模拟。
- [ ] 保留自由 OrbitControls，preset 只作为初始姿态或临时调试状态。

验收标准：

- 用户可以快速检查 item `display` 配置是否存在明显偏移、缩放或朝向问题。
- 不影响普通模型预览、截图和按需渲染性能。

## 不建议实现

- [ ] 模型编辑器、UV 编辑器、纹理绘制、Blockbench 级建模工具。
- [ ] 像素级复刻 Minecraft 客户端渲染，包括完整光照、AO、真实透明排序、渲染层、天气和世界上下文。
- [ ] 实体模型、方块实体、特殊 renderer 和完整 item stack component 模拟。
- [ ] 复制或移植 Minecraft Java 源码到插件。
- [ ] 在没有性能数据支撑前，优先开发复杂的单 material 增量更新或过度细粒度缓存。
- [ ] 截图命名模板。除非后续出现批量导出或快照对比工作流，否则优先级低。

## 建议迭代顺序

1. 先做 P0：外部 assets 刷新、点击跳转、webview dispose、性能基准和取消。
2. 再做 P1：导出选项、资源图打开预览、缓存分层。
3. 有稳定基础后做 P2 adapter：blockstate、item definition、动画纹理、atlas 简化解析。
4. P3 只在用户反馈明确时投入，避免简单预览器失控膨胀。
